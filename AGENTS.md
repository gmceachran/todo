# Notes for agents

- `core.js` is the single source of truth for the data model and is imported by the browser app, the CLI, and the tests. Every change to `tasks.json` goes through `applyOp`; add new behavior as an op there, with a test in `test/core.test.js`, rather than editing the document directly.
- Ops carry their own `at` and `today` so they can be replayed after a sync conflict; `store.js#commitOps` reloads and reapplies on a 409/422. Recurring `complete` ops include the task's `due` so a replay can't advance a task twice.
- `doc.removed` records source keys of deleted tasks so the brief's Linear sync never re-adds them; `doc.suggested` is the brief's log of Slack/email items it already offered. Neither creates tasks. `doc.briefLog` (`logBrief` op) is the brief's memory of themes and items it raised or was told to drop, and journal entries it read; `doc.focus` (`setFocus`) holds the day's focuses.
- The morning brief's instructions live in `docs/morning/SKILL.md`, standalone (it doesn't use `anthropic-skills:morning`). The scheduled routine's prompt is the stub in `docs/morning-brief.md`, so brief changes ship by pushing to `main`.
- Category matching (`findCategory`) is deliberately loose (case, punctuation, substring) because the morning brief passes Linear project names.
- Import links (`#import=`) come from outside the app: `decodeImport` whitelists fields and caps at 50 tasks, and `normalizeSource` drops any non-http(s) URL. Keep both checks when changing the format.
- `sw.js` caches the app shell network-first; bump `VERSION` when adding files to `SHELL`.
- The app can't be connected to GitHub by an agent (it would mean typing a token). Use `?demo`, which swaps in `demo.js`'s in-memory store and prefixes all localStorage keys with `todo.demo.`.
- `mockups/` is a scratch space for design iterations and isn't committed unless asked. `board.html` and `board.css` are edited by hand; `build.sh` bundles the root modules (forced into demo mode) plus the mockup's own scripts into `board.bundle.js` so it opens from `file://`.
- The task page (`#editor`) autosaves on focusout. While a pointer is down the save waits for pointerup, because the save re-renders the board and would otherwise swallow the click that moved focus. `render()` draws only the active project and calls `syncEditor()`, which refreshes every page field except the focused one.
- Subtasks change through `addSubtask`/`updateSubtask`/`removeSubtask`, and completing a recurring task unchecks them. On the task page, a new task's subtasks are drafted by running the same ops against a throwaway doc, then passed in its `add` op. `renderSubtasks` leaves the list alone while focus is inside it, so a handler that changes the list (remove) moves focus to the add input first.
